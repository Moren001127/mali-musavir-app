# Fatura Muhasebecisi — Reçeteler (PLAN/17)

Ortak: mükellef adı çoklu eşleşirse DUR, tek satır soru. Kuru testte kesilen adım "yapılacaktı"; sonrası ÇAĞRILMAZ. Rapora "Kuru testte gerçek yapılan işler: <liste|yok>" satırı zorunlu. fm_onayla, Mihsap çekimi, GİB gönderimi her zaman Muzaffer Bey. KDV Kontrol bu ajanın işi DEĞİL (Beyanname Uzmanı R1). Dönem: Fatura Merkezi 'YYYY-MM'.
Adım satırı: n) yap — araç — kademe — bekleme — başarı — hata.

## R4 — Fatura muhasebeleştirme (Fatura Merkezi → Luca fiş)
Tetik: "muhasebeleştir", "hesap ata", "Luca'ya at", "X'in Ağustos faturalarını işle".
1) Dönem özeti; belge 0 ise R5'i dene, sonra dur; hesap planı bayat → "hesap planı yenilenmeli (Muzaffer Bey: Fatura Merkezi > planı yenile)" — fm_donem_ozeti — oku — senkron — sayaçlar — belge 0 → R5.
2) Okunmamışları AI okumaya ver (≤100) — fm_belge_listele(durum=okunmadi) → fm_ai_ile_oku — portal_yaz_agir (Max kotası; kuru testte yapılmaz) — asenkron, job id yok: fm_belge_listele ile ocrStatus izle, ~2 dk/100 belge — okundu sayısı arttı — kuru test → "yapılacaktı", adım 3'te yalnız zaten okunmuş belgeler değerlendirilir.
3) Uyumsuzları değerlendir; demirbaş/tevkifat/mükerrer/iade → işaretle, karar verme; emin değilsen hesap BOŞ — fm_uyumsuzluklar → fm_belge_detay → fm_hesap_plani_ara → get_firma_hafizasi (oku) → fm_hesap_ata → fm_isaretle (portal_yaz_agir: kuru testte yapılmaz → "yapılacaktı"; öneri ve işaret listesi yine raporda + adım 4 onay kaydında yazılır) — senkron — her belge: öneri (kaynak AJAN) ya da işaret — KULLANICI satırına dokunma. fm_hesap_plani_ara ATLANMAZ: fm_hesap_ata'dan önce kod mükellefin GÜNCEL planında yaprak hesap olarak doğrulanır; "aynı satıcının başka belgesinde bu kod var" tek başına yetmez (pilot 2026-09-13: plan araması hiç çağrılmadan 3 öneri yazıldı). Aynı içerik dönemde iki farklı hesaba (ör. 740 ↔ 153) işlenmişse öneri yazma, "hesap politikası" maddesi olarak onaya sun.
4) "Onayınızı bekleyen" listesi (fm_onayla ekibe kapalı) — create_pending_action — portal_yaz — — — onay kaydı açıldı — "KAYDEDİLEMEDİ:". Tür: yeni cari kartı / plan yenileme gibi fiziksel iş → 'istek'; hesap kararı → 'onay'.
5) Muzaffer Bey onaylayıp "canlı" dediyse Luca'ya gönder ve işi bekle (INVOICE_POST, 15 dk) — fm_luca_gonder → luca_is_bekle {jobId, maxSaniye:60} — luca_yaz / oku — asenkron, ≤60 sn/çağrı, ≤15 çağrı — done — failed → lucaErrorMessage rapora, tekrar Muzaffer Bey'de; kuru test → "yapılacaktı".
Sayı dili: "hazır" = portalda Hazır durumundaki belge (onaya sunulmuş, tamam); "eşleşmiş" = hesap + cari satırları dolu ama henüz Hazır olmayan belge. İkisini ayrı say, birini diğerinin yerine yazma. Görev "hazır olanları listele" diyorsa Hazır belgeleri belge no + satıcı + tutar ile (≤10 satır) yaz; fazlası "…ve N belge daha".
Rapor (00_ORTAK §5 başlıkları içinde): FATURA MERKEZİ — <Mükellef> <Ağustos 2026> / belge <n> · okunmamış <> · hazır <> · eşleşmiş <> · kod eksik <> · çelişki <> / şüpheli: demirbaş <n> · tevkifat <n> · mükerrer <n> · iade <n> (0 ise 0 yaz) / Onayınızı bekleyen: <liste> / Luca gönderimi: <durum | yapılacaktı> / Kuru testte gerçek yapılan işler / Kime döndü: Muzaffer Bey (satır zorunlu).
Dil (pilot 2026-09-13): araç çağrıları ARASINDA metin yazma ("detayları açıyorum", "işaretliyorum" gibi süreç cümleleri Canlı akışta Muzaffer Bey'e görünür); tek metin = sondaki rapor. Durum kodları İngilizce yazılmaz: incelenecek / hazır / onaylı / reddedildi.

## R5 — Fatura çekimi: e-Fatura Sorgu / GİB e-Arşiv Sorgu → Fatura Merkezi (2026-09-15)
Tetik: "X'in Ağustos faturalarını çek (ve işle)", "e-fatura sorgula", "e-arşiv sorgula", "entegratörden al/çek". "Mihsap" geçerse ekibe KAPALI: "Mihsap çekimi Muzaffer Bey'de" de, DUR.
Yolu araç seçer (get_taxpayer.faturaCekimYolu): efatura = e-Fatura mükellefi → entegratörden e-Fatura Sorgu (alış + satış kanalları); earsiv = değilse GİB e-Arşiv Sorgu (yalnız SATIŞ). Onay kodu / PRV YOK; kuru/canlı ayrımı yeter (portaldaki Sorgula → Aktar → AI ile oku).
1) Mükellef + dönem 'YYYY-MM' + yol — list_taxpayers → get_taxpayer (faturaCekimYolu) — oku — senkron — tek mükellef, dönem, yol — çoklu eşleşme / yıl yok → tek satır soru, DUR.
2) Sorguyu başlat — fm_cekim_baslat {taxpayerId, donem, yon: alis|satis|ikisi} — luca_yaz — asenkron (arkaPlan:true; GİB → Luca ajanına EARSIV_PORTAL_FETCH işi) — {ok:true, yol, saglayicilar, mesaj}; mevcutIs:true = zaten sürüyor, yeni açma — {ok:false, neden:"HAZIR DEĞİL: …"} → aynen rapora, DUR (entegratör/şifre Muzaffer Bey'de); kuru test → "yapılacaktı", 4-5 ÇAĞRILMAZ.
3) Bitişi bekle — fm_cekim_bekle {taxpayerId, donem, maxSaniye:60} — oku — sunucuda ≤60 sn/çağrı, bitti:true dönene kadar tekrar, ≤12 çağrı — bitti:true + ozet — 12 çağrıda bitmedi → "sorgu sürüyor, bitince aktarılacak" yaz, DUR; iş failed / sorgu hata → hatayı rapora, tekrar YOK.
4) Fatura Merkezi'ne aktar — fm_cekim_aktar {taxpayerId, donem, yon} — luca_yaz — senkron (arkaPlan:true "aktarım sürüyor" → adım 3; e-Arşiv indirmeKuyrukta:true → adım 3, sonra bu adım BİR kez daha) — {ok:true, aktarilan, kontrolEdilen, zatenVar} — {ok:false, neden} (belgeler iniyor → adım 3; başka → rapora, DUR); kuru test → "yapılacaktı".
5) Hâlâ okunmamış varsa okut — fm_belge_listele(durum=okunmadi) → fm_ai_ile_oku (≤100) — portal_yaz_agir — asenkron (~2 dk/100 belge; aktarım okuma kuyruğunu zaten açar) — kuyruğa alınan — okunmamış 0 → atla; kuru test → "yapılacaktı".
6) Dönem özeti → rapor — fm_donem_ozeti (+ fm_uyumsuzluklar) — oku — senkron — sayaçlar — belge 0 → "çekimde belge gelmedi" (gelecek tarihli dönemde "fatura yok" sanma).
"işle" de dendiyse aynı koşuda R4 adım 3'ten devam; yalnız "çek" dendiyse R4'e geçme. Kuru testte adım 1, 3, 6 çalışır; 2, 4, 5 "yapılacaktı".
Rapor: ÇEKİM — <Mükellef> <YYYY-MM> / yol: e-Fatura (<entegratör>) | GİB e-Arşiv / sorgu: bitti | sürüyor | yapılacaktı | HAZIR DEĞİL: <neden> / gelen <n> · aktarılan <n> · okumaya verilen <n> · okunmamış <n> · uyumsuz <n> / "işle" dendiyse R4 raporu / Kuru testte gerçek yapılan işler / Kime döndü: Muzaffer Bey (satır zorunlu).
